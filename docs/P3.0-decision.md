## 1. B15 is a field mismatch, and folding over the native field fixes it (both options)

`spike_p3::hfs_native` is a native prototype of the HFS. It uses the protocol-spec equations with the two-phase sum-check, committed index λ and `v* = ε + ρθ`. It is generalised to any CCS template (X phase degree d+1, Y phase degree 2) and runs over **E1::Scalar**, the native field of the relation, with real Pallas Pedersen commitments.

- **R1CS, K = 2, different wiring, negative coefficients, full-field (wrapping) values: 100 alternating steps.** Every output is accepted by the succinct verifier, by the independent P2 oracle (`kn_ccs::accs::check_accs`) and by the comm_M opening. This is exactly the class `test_known_issue_b15_*` shows failing over `E::Base`.
- **Native degree-5 CCS (`power(5)` template), K = 2: 100 alternating steps,** with the same checks.
- **Rejections:**
  - An unsatisfied incoming witness fails at sum-check round 0.
  - Tampered σ and tampered round messages are rejected.
  - A wrong predicate id is rejected.
  - A tampered fold output is caught by the decider (oracle).

So the protocol algebra is sound once the field matches. What D1 decides is only **where the group operations on the other curve's points go**.

## 5. Recommendation

**Choose (a): keep the Nova fork and add CycleFold.** The reasons:

1. **B15 is fixed** by the native-field prototype. What remains is engineering whose cost we measured, and the estimate (≈ 128k per step) is no worse than today's incorrect 146k.
2. **(b) would not save the hard part.** Index commitments, holography, the two-phase sum-check and non-uniform IVC are all missing in Sonobe. (b) also discards P0–P2 infrastructure and adds dependency instability.
3. **(a′) is ruled out** by measurement.

The cost of choosing (a) is in P8: HyperNova and ProtoGalaxy become external baselines, so cross-library comparisons must carry the PLAN.md §8 disclosure.
